# 变更请求（Change Request）模板

> 复制此文件并重命名为 `CR-{三位序号}.md`（如 CR-001.md）

---

## 基本信息
- **编号**：CR-{三位序号}
- **提交日期**：{YYYY-MM-DD}
- **提交人**：__________
- **状态**：☐ 待审核 / ☐ 已批准 / ☐ 已拒绝 / ☐ 已合并
- **涉及基线**：{如 prd-v1.0，对应文档版本 V1.0}
- **Git 分支**：cr/CR-{序号}
- **关联 PR**：#{PR 编号}（GitHub Pull Request）

## 变更类型
☐ 新增需求 / ☐ 修改需求 / ☐ 删除需求 / ☐ 范围调整

## 原需求信息
- **需求编号**：{REQ-XXX-NNN}
- **原需求标题**：{原标题}
- **原需求描述**：{原描述摘要}

## 变更内容
### 新需求描述
{修改后/新增的需求描述}

### 变更理由
{为什么要改？业务驱动是什么？}

## 影响分析
- **影响范围**：{涉及哪些模块、哪些需求条目}
- **受影响的关联需求**：{列出受影响的 REQ 编号}
- **优先级变化**：{是否影响优先级排序}

## 影响评估（项目经理填写）

- **CIA 编号**：{CIA-{序号}，与 CR 一一对应}
- **CIA 状态**：☐ 待评估 / ☐ 已完成
- **评估日期**：{YYYY-MM-DD}
- **计划调整**：☐ 无需调整 / ☐ 需调整（详见 CIA 文档）

## 新基线
- **合并后版本**：{如 prd-v1.1}
- **合并日期**：{YYYY-MM-DD}
- **Git Tag**：{如 prd-v1.1}
- **合并方式**：PR merge to main

---

> **原则**：已锁定需求永远不直接修改，变更以 CR 形式附加。CR 对应 Git 分支，审核通过后通过 PR 合并到 main 并打新 tag，形成新基线版本。
